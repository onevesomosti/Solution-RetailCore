
#Анализ использованных артефактов

| Артефакт | Что дал для восстановления AS-IS | Ограничение |
| --- | --- | --- |
| Описание компании | Бизнес-цели, технологический фон, Java + Oracle + Python + .NET, on-premise, рост данных, историческая эволюция и общие проблемные зоны | Даёт только верхнеуровневую картину |
| AS-IS.puml | Обозначает границы: каналы, монолит, Oracle, .NET, Python analytics, async/batch, инструменты поддержки и внешние партнёры | Сам источник предупреждает, что существующая схема может быть неполной поэтому использована как отправная точка, а не эталон |
| interview-1-tech-lead.md | Показал реальную центральную роль монолита, распределённую логику определения стоимости и статусов, ручные вмешательства, длинные транзакции и Oracle как скрытую зависимость | Это взгляд только команды монолита, отдельные интеграции нужно сверять с их владельцами |
| interview-2-logistics.md | Раскрыл смесь REST, очередей и таблиц. Подсветил ручные настройки, split shipment, retry, дубли, различия в идемпотентности и отсутствие единого интеграционного слоя | Сосредоточен прежде всего на логистическом контуре |
| interview-3-analytics.md | Показал неоднородные источники SQL/staging/API/CSV, проблемы жизненного цикла и влияние аналитики на операционный Oracle | Аналитические представления не являются сами по себе источником истины |
| OrderProcessingService.java | Подтвердил интервью на уровне реализации: смешение ответственности, ветвление по каналам, promo fallback в Oracle, direct SQL, staging для .NET, ручной review, sync delivery/payment и DB-based retry | Это один фрагмент кода, по нему нельзя утверждать, что вся платформа устроена только таким образом |

Главный результат сверки артефактов - исходная архитектурная схема в целом верно показывает крупные элементы, но существенно упрощает реальное поведение. Интервью и код добавляют то, что особенно важно для AS-IS: распределённые бизнес-правила, разные ветки по каналам, fallback с иной семантикой, ручные переходы статусов, retry через Oracle, интеграции через таблицы, неодинаковые гарантии async-обмена и отсутствие единой модели заказа.
