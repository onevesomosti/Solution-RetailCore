
# Architecture Canvas RetailCore

| Блок | RetailCore AS-IS |
| --- | --- |
| Ценностное обоснование | Платформа должна быстрее адаптироваться к новым требованиям, выдерживать рост нагрузки и более предсказуемо обрабатывать заказы. Ближайшая цель — получить понимание реального состояния платформы. Далее — подготовить основу для новых сервисов и постепенного отказа от Oracle и других иностранных компонентов |
| Ключевые заинтересованные стороны | Клиенты, бизнес, команды заказов и оформления, клиентская поддержка, команда аналитики, команда инфраструктуры |
| Ключевые функции | - Оформление заказа<br> - Расчёт стоимости и скидок <br> - Резервирование и обработка заказа<br> -Создание платёжной сессии<br> - Выбор и резервирование доставки<br> - Управление статусами<br> - Партнёрские интеграции<br> - Поддержка ручных и исключительных сценариев<br> - Аналитика и отчётность<br> |
| Требования к качеству | - Устойчивость базового order flow<br> - Предсказуемое поведение в пиках<br> - Изменяемость<br> - Прозрачность состояния заказа<br> - Согласованность представлений данных<br> - Прослеживаемость заказа<br> - Возможность развития без критического риска для текущих операций |
| Деловой контекст | Заказы поступают из интернет магазина, мобильных каналов и маркетплейсов. RetailCore зависит от платёжных провайдеров, служб доставки и партнёрских систем. Поддержка использует административные инструменты для разбора исключений. Аналитика и BI потребляют данные платформы |
| Ключевые решения AS-IS | - Java-монолит является центральным оркестратором<br> - Oracle используется одновременно как операционная БД, место части бизнес-логики и интеграционный механизм<br> - Интеграции реализованы через REST/синхронные вызовы, очереди, batch и CSV<br> - Часть сценариев использует ручную обработку |
| Составные части системы | - Интернет-магазин и мобильные каналы <br> - Java-монолит: Checkout/Order API, Order Processing, Pricing & Promo, Status Management, Payment Orchestration, Delivery Routing<br>  - Oracle<br> - .NET integration service<br> - ython analytics jobs<br> - Async/batch exchange<br> - Admin/Support tools |
| Технологии | - Java, Oracle, Python, .NET; REST/синхронные интеграции<br> - Очереди и batch<br> - SQL/staging tables<br> - CSV <br> - on-premise инфраструктура на физических серверах с ограниченной виртуализацией |
| Риски и недостающая информация| - Высокая связность монолита и Oracle<br> - Длинные транзакции заказа<br> Распределённая логика стоимости, промо, доставки и статусов<br> - Неодинаковое поведение разных каналов<br> -Ручные вмешательства<br> - Риск дублей при retry<br> - Аналитическая нагрузка на операционную Oracle<br> -Отсутствие единого источника правды<br> - Слабая сквозная наблюдаемость<br> - Не определены численные параметры производительности, восстановления, консистентности и допустимой деградации |
